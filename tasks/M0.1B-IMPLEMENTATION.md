## Locked rules (user approved 2026-11-19)
- Standard 52-card Klondike, draw one.
- Unlimited stock redeals: draw stock top to waste; when stock empty, recycle waste into stock in the correct original draw order, without shuffling. Define exact orientation in code/tests.
- Tableau: seven columns, initial counts 1..7, only each top card face up. Descending ranks and alternating red/black suits. Empty tableau accepts a king-led run only.
- Foundations: four piles, build A through K in matching suit, one card at a time.
- A valid face-up tableau run can be moved, with no face-down cards included.
- Win when all 52 cards are on foundations.
- Undo game-state-changing actions, not cursor/selection changes.

## Existing user-specific interaction contract to preserve
See tasks/M0-CONTROLS.md. B picks up the maximum legal run from the selected card; B drop tries whole candidate first, then successively shorter suffixes, choosing the longest legal suffix. Untransferred leading cards stay in source order. No authoritative mutation during preview/carry; commit only a validated transfer atomically. M0.1B implements the pure rule evaluator and atomic transaction operations, NOT controller bindings or animated carry.
- Avoid ambiguous terminology: with candidate [9S,8H,7C,6D] ordered bottom-to-top, shorter suffixes are [8H,7C,6D], [7C,6D], [6D].
- Only a valid suffix may move. After any transfer that exposes a facedown tableau top, flip it as part of the same undoable transaction.
- Explicitly decide/test foundation-to-tableau reversals and foundation-to-foundation behavior per standard Klondike; no foundation-to-foundation transfer.
- Ensure stock/waste action order, recycling and undo are consistent and reversible.

## Implementation
1. Inspect existing repo architecture, devkit guidance, M0.1A report and tests. Reuse model and seeded deck; keep generic card/deck/pile modules independent of Klondike.
2. Add Klondike-specific state with 7 tableau piles, 4 foundations, stock, waste, face states, draw/recycle count or phase as needed, and win state.
3. Implement seeded deterministic deal with all 52 identities conserved and correct tableau/stock distribution.
4. Pure legality evaluation for single cards and runs; enumerate longest legal suffix at destination without mutating state.
5. Transactional operations: stock draw, waste recycle, tableau/waste/foundation transfers, tableau top reveal, undo history. Invalid operations leave state byte-for-byte or structurally unchanged.
6. Keep state operations independent of SDL, keyboard and render loop. No new UI required; optional deterministic command-line rules test harness.
7. Explicitly document edge cases: stock exhausted, waste empty, full redeal, undo recycle, foundation reversal, invalid/empty piles, king empty column, repeated draw/recycle.
8. Unit tests: seeded deal repeatability, all cards unique, legal/illegal moves, longest-suffix examples, reveal + undo, draw/recycle order + undo, no mutation on failed moves, winning-state detection, conservation after long random legal action sequences.
9. Strict build and CTest passing; no claim of handheld validation. Record tests and limits in tasks/M0.1B-REPORT.md and update project roadmap/state.
