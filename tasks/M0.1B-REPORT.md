## Rule and transaction details

All pile arrays are bottom-to-top. Column-wise deal consumes seeded deck array
indices 0..27; columns have 1..7 cards with only each top face up. The remaining
stock is stored as indices 51..28 bottom-to-top, so index 28 draws first.
Draw transfers one stock top face up onto waste. Empty-stock recycling reverses
all surviving waste cards face down into stock, with no shuffle or redeal limit.
Its oldest surviving waste card is then next to draw. Draw on empty stock,
recycle on nonempty stock and recycle on empty waste are rejected. Empty stock
and waste together cause neither action to change state.

Only valid face-up suffixes can leave tableau; waste/foundation sources provide
their top card only. Tableau destinations build down in alternating colours;
empty columns accept only king-led suffixes. Foundations start with an ace and
build up in matching suit one card at a time. Their tops may return to tableau;
no foundation-to-foundation transfer is allowed, including ace-to-empty.

Exact move legality and longest-suffix proposal evaluation take const state.
For [9S,8H,7C,6D], destinations 10H, 9C, 8D and 7S choose respectively the whole
run, [8H,7C,6D], [7C,6D] and [6D]. Untransferred cards stay at source in order.
Source selection restricts the candidate; evaluators never include a lower
index than selected. Invalid candidates/destinations leave state/history alone.

Successful actions validate a copied result and allocate the previous full
state snapshot before changing authoritative state/history. Any newly exposed
hidden tableau top flips in the same transaction. Undo restores all piles and
faces together; win is derived, so undo/reversal cannot leave a stale win flag.
No preview, focus or cursor changes enter the rules/history API.

## Verification

Environment: Fedora 43 Toolbox, GCC 15.3.1, SDL2 2.32.74. No packages installed.
Strict C17 compilation uses `-Wall -Wextra -Wpedantic -Werror`.

```sh
cmake -S . -B build/desktop -G Ninja
cmake --build build/desktop
ctest --test-dir build/desktop --output-on-failure

cmake -S . -B build/rules-only -G Ninja -DCARDGAME_BUILD_PREVIEW=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build/rules-only
env -u DISPLAY -u WAYLAND_DISPLAY ctest --test-dir build/rules-only --output-on-failure
ldd build/rules-only/klondike-tests

cc -std=c17 -Wall -Wextra -Wpedantic -Werror -fanalyzer -Isrc -c src/klondike.c -o build/klondike-analyzed.o
./build/desktop/card-preview --smoke
./build/desktop/card-preview --capture build/desktop/m01b-tableau.bmp
./build/desktop/card-preview --stress --theme wine --capture build/desktop/m01b-stress.bmp
```

Results: full build **3/3 CTest suites pass**; rules-only Release **2/2 pass**
without a display. `ldd` reports libc and the loader only for the rules test,
with no SDL linkage. GCC's static analyzer emits no diagnostics. Sanitizers were
not run for this milestone; static analysis is not a sanitizer result.

Tests cover 1,000 repeated seeded deals and independent identity/distribution
checks, all four longest-suffix outcomes, no-fit/selection/invalid-index cases,
king-to-empty, same-colour/wrong-rank rejection, buried/hidden source rejection,
ace/suit/rank foundation checks, foundation reversal and explicit forbidden
foundation-to-foundation ace transfer. Full and partial transfers preserve order;
reveals and foundation transfers undo as one action. Waste order, five complete
redeals, premature recycle rejection, undo/reapply recycle, and redeal after
removing aces to foundations are checked. Win, undo win, foundation reversal from
a won state, invalid complete states, empty actions, reset/dispose and unchanged
state/history on rejected operations are exercised.

32 seeds × 1,000 legal actions produced **26,024 transfers, 5,260 draws and
716 redeals**. Each action is replayed deterministically in a second game;
independent test-side counts check all 52 unique identities. Periodic undo/new
branches reproduce the replay state, and unwinding all history restores each
initial deal. The M0.1A foundation and rendering suites continue to pass.

Desktop smoke launch succeeded. Both newly captured BMPs are exactly 640×480
and pixel-identical to the M0.1A PNG evidence in `docs/screenshots/`, compared
with Pillow ImageChops. No interactive UI/controller or device test is claimed.

## Acceptance and limits

All scoped M0.1B local acceptance criteria pass: deterministic SDL-free rules,
correct draw/redeal and placement legality, longest-suffix atomic transfer,
complete undo including flips and stock order, conservation and documented tests.
The engine checks complete-state invariants before evaluating/applying moves.
History uses dynamically allocated complete snapshots and grows with committed
actions until undo, reset or dispose; allocation failure rejects an action
without mutation. Allocation-failure injection was not tested.

No new gameplay UI, carry rendering, bindings, animation, final overflow, save
format, device packaging or court art is implemented. M0.1A remains a static
preview. No RG35XXSP execution or handheld legibility is verified.
