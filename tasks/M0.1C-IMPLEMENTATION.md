## Goal
Produce the first actually playable 640x480 desktop Klondike using existing C17 SDL2 rendering and pure rules engine. Keyboard emulates RG35XXSP controls. Keep reusable input/interaction code separate from Klondike-specific policy. No device build yet.

## Locked control contract
- D-pad Left/Right: move between piles in current area, including while carrying.
- D-pad Up/Down: select a movable face-up tableau card, never a hidden card. Default selection is bottom of the maximal valid face-up run; Up steps toward top of pile, Down toward bottom of selectable run. When carrying, navigation changes destination only, not selected source/candidate.
- L1/R1: cycle areas in order Draw (stock,waste) -> Tableau (7) -> Foundations (4) -> Draw, reverse with L1. On entering an area, restore last focused valid pile in that area; initially stock, tableau column 0, foundation 0.
- L2/R2: jump to first/last pile of current area, also while carrying.
- B: if not holding, pick up selected valid face-up suffix (tableau, waste or foundation top). If holding, try destination-aware longest legal suffix. A successful drop commits exactly once; if invalid, remain holding and show feedback without state mutation. B on the source pile cancels held selection without mutation.
- A: if holding, cancel and return focus to source, without authoritative state change. If not holding and waste has a top card, create a pending waste-card carry with current cursor position as destination, irrespective of current area; B attempts placement. If waste empty, no action with feedback. A never commits prematurely.
- X: when not holding, auto-move the selected eligible tableau card or top waste card to a foundation using pure rules; choose first legal foundation index deterministically. Never auto-move a multi-card run. When holding, ignore with feedback (no hidden commit). Do not implement speculative safety heuristic.
- Y: when not holding, draw one if stock nonempty, else recycle waste if stock empty and waste nonempty, else no-op. When holding, ignore with feedback. Preserve draw/recycle undo granularity as separate committed actions.
- Select: if holding, cancel pending selection first (without consuming undo), otherwise undo most recent committed action. Focus must be made valid after undo.
- Start: pause overlay with Resume, New Game (confirm before discarding current game), Quit. Pause must not mutate game; no gameplay actions while paused.

## Keyboard mapping
Use a documented, configurable desktop keyboard mapping for D-pad, A/B/X/Y, L1/R1/L2/R2, Start/Select; avoid hardcoding Linux input-device keycodes. Prefer arrow keys for D-pad, Z=B, X=A, A=X, S=Y, Q/E=L1/R1, 1/3=L2/R2, Enter=Start, Backspace=Select, but verify collisions and use consistent labels in README. Keep event mapping separate from game action dispatch. Existing preview T/B theme/stress keys must not conflict in gameplay; retain separate preview mode or move debug keys to clearly documented alternatives.

## Architecture and state
- Keep KlondikeGame authoritative; UI holds only focus, selected source/index, pending candidate, pause state and feedback.
- No authoritative state mutation during pickup, navigation, destination preview or cancellation.
- Held stack visual is a transient overlay showing entire candidate sequence, even when only a suffix will transfer; source model remains intact. Prevent misleading duplication by visually distinguishing/ghosting the source during carry.
- On B drop use klondike_longest_suffix for preview and klondike_drop to commit; retained source prefix remains correctly rendered. Successful transfer may snap instantly; no animation requirement.
- On an invalid B drop, briefly show a clearly visible RED OUTLINE around the entire held card/stack visual (not merely the destination pile), then return to normal held appearance. Keep carrying the same cards, with unchanged authoritative game state, cursor and undo history. The feedback must be transient, non-blocking and retriggerable on subsequent invalid attempts; avoid relying on sleeps that freeze the event loop. Choose and document a short duration (suggest 200–350 ms) and test the visual state transition. Reserve a semantic invalid-action/error event for a future sound effect; do not add audio or new sound dependencies in M0.1C.
- Build scene from actual KlondikeState rather than M0.1A deterministic preview fixture. Retain standalone static preview for regression.
- Ensure selection/focus remains valid across reveals, draws, undo, new game, empty piles and stock recycle.
- Focus and pending state never enter rules undo history.
- Preserve fixed top status bar, no bottom controls bar, grouped rank/suit indices, existing card back themes.
- Tall tableau overflow: implement minimal deterministic readable layout or viewport/scroll adjustment sufficient to keep selectable cards and destination visible, without requiring final polished overflow design; do not silently hide selectable cards.
- On win, show simple win state and allow new game.

## Test requirements
- Unit tests for focus and area cycling, first/last jumps, selectable run and hidden-card bounds, pickup/cancel/invalid drop, B on source, A from any area, A with empty waste, carrying across areas, X deterministic single-card foundation move, Y draw/recycle, Select cancel vs undo, pause gating and new game confirmation.
- Verify entire held candidate is visually represented and no authoritative mutation occurs before successful drop. Test shorter legal suffix and resulting source prefix.
- Test invalid-drop red outline onset, automatic expiry, retrigger on repeated invalid drop, and preservation of held cards/state/undo. Ensure a future error-sound event can be attached without adding sound playback now.
- Offscreen render smoke/capture at exact 640x480, check no bottom bar and indexes remain visible.
- Preserve M0.1A and M0.1B tests, strict compiler warnings, SDL-free rules build.
- Manual desktop keyboard play-through (or clearly document if unavailable), including at least a stock cycle, tableau move, invalid drop, cancel, undo and restart.
- Record exact commands/results in tasks/M0.1C-REPORT.md. No claims of RG35XXSP hardware testing or completed device mappings.

## Resource and robustness follow-up
- Snapshot undo currently grows unbounded. Add a configurable bounded history policy if straightforward and covered by tests; otherwise document as a blocker for eventual device deployment, not for desktop M0.1C.
- Allocation-failure injection for undo is desirable, but do not destabilize the milestone or misreport as tested.
- Preserve modularity for future games such as 500; don't put Klondike rules in generic input or renderer modules.
