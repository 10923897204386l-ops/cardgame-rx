## Objective
Implement the smallest runnable desktop prototype at a logical 640x480 resolution, with reusable card/deck/pile data structures and a deterministic sample tableau. Do not implement Klondike move legality or controller transactions in this milestone.

## Architecture
- Follow existing repository devkit and workflow conventions; inspect existing files before adding dependencies or deciding package structure.
- Separate pure game state/model from layout calculations, drawing, and platform input.
- Card: immutable identity (suit, rank); face-up/down belongs to pile/game state or a distinct card instance state; avoid duplicate identity within a deck.
- Standard 52-card deck: four suits, ranks A,2–10,J,Q,K; deterministic seedable Fisher–Yates shuffle with optional nondeterministic seed for normal play.
- Pile: ordered cards with top/bottom semantics, independent of screen coordinates; provide safe read operations. Keep mutating moves out of scope.
- Expose pure layout functions that return card rectangles, including exposed tableau strips and configurable overlap.
- Tests for deck uniqueness, rank/suit distribution, shuffle reproducibility, pile order, bounds and layout.

## Rendering
- Native logical canvas 640x480. Window may scale by integer factors, preserving aspect ratio.
- Fixed top status bar only; no bottom toolbar.
- Draw stock, waste, four foundations and seven tableau columns as a static Klondike preview (no gameplay claims).
- Traditional ivory playing-card faces with high-contrast red/black suits; conventional pip counts on number cards and recognizable court cards.
- Place rank and suit glyph immediately beside each other in upper-left corner. All exposed face-up tableau strips must show the grouped index.
- Face-down cards use a theme-customizable card back, with a built-in default.
- Use crisp pixel-aligned rendering, no assumption that previous chat mockup is an available asset.
- Layout constants configurable rather than hard-coded throughout renderer.
- If full traditional court art is not available/licensed, use a clearly identified temporary court illustration, not an assertion that final art is complete.
- Include a stress-preview scene for tall tableau piles, without implementing final overflow strategy yet.

## Deliverables
1. Runnable desktop preview command documented in README.
2. Reusable card, deck, pile and layout modules.
3. Deterministic sample tableau plus a tall-stack stress scene.
4. Unit tests runnable without display.
5. Screenshot capture instructions at exact 640x480.
6. Brief milestone report with files changed, test results, known gaps, and recommended M0.1B handoff.

## Acceptance criteria
- Application launches on Fedora Kinoite development environment.
- All 52 identities are unique and correctly distributed; seeded shuffles reproduce.
- Renderer uses 640x480 logical coordinates and draws no bottom bar.
- Every visible face-up exposed strip keeps rank/suit legible.
- No game-specific rules leak into generic card/deck/pile model.
- Tests pass locally and results are reported accurately.
- No claim of hardware testing until tested on the RG35XXSP.

## Scope exclusions
- Klondike legality, automatic suffix placement, held-stack movement, undo, save/load, animations, controller mappings, final overflow strategy, physical device packaging.

## Workflow
Implement on this branch as small reviewable commits; do not push directly to main. Run tests, document evidence, open a squash-merge PR after acceptance. Preserve existing design documentation and use repo-local handoff notes so later ChatGPT/Codex/Warp sessions can resume.
